**MeshBackground.tsx (per D-03, D-08):**

Simple wrapper component that renders a fixed-position canvas and delegates all Three.js logic to the hook.

```typescript
import { useRef } from 'react'
import { useMeshBackground } from '../hooks/useMeshBackground'

interface Props {
  active: boolean  // true when content zone is visible (!heroVisible)
}

export default function MeshBackground({ active }: Props) {
  const canvasRef = useRef<HTMLCanvasElement>(null)
  useMeshBackground(canvasRef, active)

  return (
    <canvas
      ref={canvasRef}
      style={{
        position: 'fixed',
        top: 0,
        left: 0,
        width: '100vw',
        height: '100vh',
        zIndex: 5,           // Above aquarium (0) but below content zone (10)
        pointerEvents: 'none', // Scroll events pass through to content
        opacity: active ? 1 : 0,
        transition: 'opacity 0.6s ease',
      }}
    />
  )
}
```

**useMeshBackground.ts (per D-01 through D-08):**

This is the core hook. It manages the full Three.js lifecycle:

1. **Scene setup:** WebGLRenderer (alpha: true, antialias: true), PerspectiveCamera (FOV ~50, positioned at z = 10-15 to see all meshes), Scene with no background (transparent).

2. **Mesh loading:** Load 3 meshes from `public/meshes/*.obj` using OBJLoader from `three/addons/loaders/OBJLoader.js`. If OBJ files were not prepared (fallback approach), create geometries programmatically:
   ```typescript
   const geometries = [
     new THREE.IcosahedronGeometry(1, 1),      // bunny stand-in
     new THREE.TorusKnotGeometry(0.8, 0.3, 64, 8), // dragon stand-in
     new THREE.DodecahedronGeometry(1, 0),      // teapot stand-in
   ]
   ```

3. **Material per mesh (per D-04, D-07):** MeshBasicMaterial with wireframe: true, transparent: true, depthWrite: false, and distinct muted tint colors:
   ```typescript
   const MESH_COLORS = [
     { r: 100 / 255, g: 220 / 255, b: 255 / 255 }, // soft cyan
     { r: 255 / 255, g: 120 / 255, b: 100 / 255 }, // coral
     { r: 255 / 255, g: 210 / 255, b: 100 / 255 }, // warm yellow
     { r: 120 / 255, g: 255 / 255, b: 180 / 255 }, // soft green
   ]
   ```
   Opacity: 0.12 (within the 8-15% range per D-07).

4. **BouncingMesh interface:**
   ```typescript
   interface BouncingMesh {
     mesh: THREE.Mesh
     velocity: THREE.Vector3
     radius: number
     rotationSpeed: THREE.Vector3
   }
   ```

5. **Initialization:** For each loaded mesh, compute bounding sphere via `geometry.computeBoundingSphere()`, normalize scale so all meshes are roughly the same visual size (scale to fit within a 2-unit bounding sphere), assign random initial position within visible bounds, assign random velocity (slow: magnitude ~0.5-1.5 units/sec), assign random rotation speed (slow: 0.1-0.3 rad/sec per axis).

6. **Animation loop (per D-05, D-06, D-08):**
   ```typescript
   let lastTime = 0
   const FPS_CAP = 1000 / 30  // 30 FPS throttle per D-08

   function animate(time: number) {
     rafId = requestAnimationFrame(animate)

     // Throttle to 30 FPS
     if (time - lastTime < FPS_CAP) return
     const dt = Math.min((time - lastTime) / 1000, 0.1) // cap dt to prevent large jumps
     lastTime = time

     // Skip rendering when not active (per D-08)
     if (!activeRef.current) return

     updatePhysics(objects, dt, bounds)
     renderer.render(scene, camera)
   }
   ```

7. **Physics update function (per D-05, D-06):**
   - Update positions: `obj.mesh.position.addScaledVector(obj.velocity, dt)`
   - Update rotations: `obj.mesh.rotation.x += obj.rotationSpeed.x * dt` (similarly y, z)
   - Reflect off bounds (DVD bounce): if position +/- radius exceeds camera frustum bounds, negate the corresponding velocity component
   - Bounding-sphere collisions (elastic): for each pair, if distance < sum of radii, swap velocity components along collision normal and separate overlapping meshes (exact code from RESEARCH.md Pattern 3)

8. **Bounds calculation:** Convert camera frustum to world units at the mesh plane (z=0):
   ```typescript
   const vFov = camera.fov * Math.PI / 180
   const halfH = Math.tan(vFov / 2) * camera.position.z
   const halfW = halfH * camera.aspect
   const bounds = { w: halfW * 2, h: halfH * 2 }
   ```

9. **Resize handling:** Add `window.addEventListener('resize', onResize)` that updates renderer size, camera aspect, and bounds.

10. **Cleanup (per RESEARCH.md Pitfall 1):** In the useEffect cleanup:
    ```typescript
    return () => {
      cancelAnimationFrame(rafId)
      window.removeEventListener('resize', onResize)
      scene.traverse((obj) => {
        if (obj instanceof THREE.Mesh) {
          obj.geometry.dispose()
          if (obj.material instanceof THREE.Material) obj.material.dispose()
        }
      })
      renderer.dispose()
      renderer.forceContextLoss()
    }
    ```

11. **Active state tracking:** Use `useRef` for the active boolean so the animation loop can read it without re-running the effect:
    ```typescript
    const activeRef = useRef(active)
    useEffect(() => { activeRef.current = active }, [active])
    ```

12. **TypeScript strictness:** All variables typed. Unused parameters prefixed with `_`. No `any` types -- use proper Three.js types. The hook returns void (no state exposed to the component).

Export the hook as: `export function useMeshBackground(canvasRef: React.RefObject<HTMLCanvasElement | null>, active: boolean): void`
